# Design-Focused Planning Guidelines

## Design Analysis Process

Before creating the todo list, analyze the idea through a design lens:

### 1. Identify Product Category

Determine what type of product this is:

- **SaaS/Tech Tool** - Project management, analytics, productivity software
- **Consumer App** - Social, entertainment, lifestyle apps
- **E-commerce** - Online stores, marketplaces, product catalogs
- **Portfolio** - Personal portfolios, agency showcases, creative work
- **Blog/Content** - News sites, blogs, publications, documentation
- **Dashboard** - Admin panels, analytics dashboards, internal tools
- **Agency/Professional** - Service businesses, consultancies, studios
- **Community** - Forums, membership sites, social platforms
- **Finance/Trust** - Banking, legal, healthcare, security services

### 2. Determine Target Audience

Who will use this?

- **Enterprise buyers** - Decision-makers, IT professionals, business users
- **Consumers** - General public, casual users, everyday people
- **Creators** - Artists, designers, writers, makers
- **Developers** - Technical users, engineers, programmers
- **Small businesses** - Entrepreneurs, local businesses, startups
- **Professionals** - Lawyers, doctors, consultants, specialists

### 3. Define Emotional Positioning

How should the design feel?

- **Trustworthy** - Reliable, secure, professional, established
- **Exciting** - Dynamic, energetic, bold, cutting-edge
- **Friendly** - Approachable, warm, welcoming, casual
- **Premium** - Sophisticated, luxurious, high-end, exclusive
- **Playful** - Fun, whimsical, creative, lighthearted
- **Authoritative** - Expert, powerful, commanding, serious
- **Minimal** - Clean, simple, focused, uncluttered
- **Bold** - Confident, striking, memorable, distinctive

### 4. Identify Key Content Needs

Based on product category, what sections are essential?

- **SaaS** - Features, integrations, pricing, testimonials, product screenshots
- **Portfolio** - Project grid, case studies, about, skills, contact
- **E-commerce** - Product showcase, categories, trust signals, shopping features
- **Blog** - Post listings, featured content, author info, categories
- **Dashboard** - Stats overview, data visualizations, activity feeds, quick actions
- **Agency** - Services, portfolio, team, process, credentials
- **Community** - Member showcase, activity, join CTA, value proposition

## Visual Direction Guidance

### Color Direction with Emotional Intent

Don't just specify colors—explain the emotional purpose:

- ❌ Bad: "Use blue and white"
- ✅ Good: "Trustworthy blues that feel enterprise-ready without being stuffy, paired with crisp whites for clarity"

- ❌ Bad: "Orange color scheme"
- ✅ Good: "Warm and inviting oranges that feel energetic but not aggressive, creating approachability"

- ❌ Bad: "Purple theme"
- ✅ Good: "Rich purples that convey creativity and premium positioning without feeling generic-tech"

**Color direction should include:**

- Emotional intent (what feeling the colors create)
- Category positioning (how it fits the product type)
- Differentiation note (what makes it NOT the default choice)

### Typography Mood

Describe how typography should feel, not just what fonts to use:

- **Friendly but professional** - Approachable without being playful, clear without being corporate
- **Bold and confident** - Strong hierarchy, purposeful weight mixing, commanding presence
- **Elegant and refined** - Sophisticated, generous spacing, light weights for display
- **Technical and precise** - Monospace accents, clear hierarchy, data-friendly
- **Creative and expressive** - Distinctive display type, personality in headings, artistic flair
- **Minimal and focused** - Restrained type scale, consistent weights, whitespace emphasis

### Layout Approach

Specify what to avoid AND what to use instead:

**Default patterns to avoid:**

- Icon grids for features/services
- Empty-right hero compositions
- Centered-text-on-colored-band CTAs
- Generic three-column layouts
- Stock photo hero backgrounds

**Alternative approaches to specify:**

- Staggered two-column with alternating image/text
- Bento-style grid with varied card sizes
- Asymmetric hero with product shot or graphic element
- Integrated CTAs within distinctive sections
- Full-bleed imagery with overlaid content
- Single-column with generous whitespace
- Diagonal or curved section breaks

## Cliché Avoidance by Category

### Tech/SaaS/Modern

**Avoid:** Dark mode with cyan/purple gradients, blue as default, icon grids, generic screenshots  
**Use:** Light mode with unexpected accent colors (warm/earth tones), inline examples, real UI screenshots  
**Direction:** "NO dark mode with cyan/purple gradients. Light base with ONE bold accent (warm/earth tones, not blue). Show features through examples, not icon grids."

### Creative/Bold/Agency

**Avoid:** Energy only in hero then generic sections, bold colors fading to gray, creative hero with boring footer  
**Use:** Maintain energy throughout, bold choices in CTA/footer, unexpected elements in "boring" sections  
**Direction:** "CRITICAL: Maintain creative energy throughout. Footer/CTA must match hero boldness. Don't get safer as page progresses."

### Minimal/Clean

**Avoid:** Minimal as excuse for boring, identical whitespace, safe centered layouts, no distinctive elements  
**Use:** Layout innovation, asymmetric structures, purposeful varied whitespace, bold typographic element  
**Direction:** "Since minimal, layout must differentiate. Require asymmetric composition. Use varied whitespace purposefully. Include bold typographic element."

### Professional/Trust/Finance

**Avoid:** Navy blue + gray/gold, generic stock photos, safe template layouts, basic trust badges  
**Use:** One distinctive element for memorability, premium execution, unexpected structural choices, quality-driven trust  
**Direction:** "Avoid generic corporate blue-gray. Include ONE distinctive element (oversized typography, unusual grid, bold whitespace) for memorability, not just 'professional'."

### Consumer/Friendly/E-commerce

**Avoid:** Colored circles with icons, generic rounded corners everywhere, pastel without personality, placeholder graphics  
**Use:** Actual illustrations/stylized graphics, purposeful playful elements, vibrant colors with character, custom graphics  
**Direction:** "NO colored circles with icons. Require actual illustrations or bold graphic shapes/patterns—not placeholder circles."

## Section-Specific Instructions

### Hero Section

**Avoid:**

- Text-left, empty-right composition
- Generic hero background image
- Centered text with button below
- No social proof or credibility

**Include instead:**

- Visual balance (if text left, add product shot/graphic right)
- Social proof element below fold (logos, stats, testimonial snippet)
- Distinctive composition (asymmetric, overlaid, integrated)
- Purpose-driven imagery, not generic backgrounds

**Example instruction:**
"Hero should have visual balance—if text is left-aligned, right side needs product shot, illustration, or graphic element. Include social proof element (logos, stats, or testimonial snippet) below the fold line. Avoid generic background images."

### Features Section

**Avoid:**

- 3-4 column icon grid (the default AI pattern)
- List of features with descriptions
- Generic icons for each feature
- No visual examples

**Include instead:**

- Show, don't list (inline examples, screenshots, micro-interactions)
- Staggered layout or bento grid with varied sizes
- Actual product UI or visual demonstrations
- Alternating image/text sections

**Example instruction:**
"DO NOT use a standard icon grid for features. Instead, use a staggered two-column layout with alternating image/text sections, or a bento-style grid with varied card sizes. Show features through examples or screenshots, not icon lists."

### Social Proof

**Category-appropriate:**

- **Consumer products** - User testimonials with photos, ratings, reviews
- **B2B/Enterprise** - Company logos, credentials, case study stats
- **Creative/Agency** - Portfolio examples, client work, awards
- **Technical** - Integration logos, developer testimonials, GitHub stars

**Avoid:**

- Generic testimonial cards identical across categories
- Stock photo testimonials
- Credential sections without personality

**Example instruction:**
"Social proof should match category: [consumer = testimonials with photos | B2B = company logos and credentials | creative = portfolio examples]. Avoid generic testimonial card layouts."

### CTA Section

**Avoid:**

- Centered text on colored band (the most common AI pattern)
- Generic "Get Started" with button below
- Identical to every other CTA section
- Afterthought placement

**Include instead:**

- Asymmetric layout
- Integrated into distinctive section
- Visual element or graphic
- Unexpected composition

**Example instruction:**
"DO NOT use the standard centered-text-on-colored-band pattern. Try an asymmetric layout or integrate the CTA into a more distinctive section with visual elements."

### Footer

**Avoid:**

- Afterthought with degraded quality
- Generic link lists in columns
- Design energy drops off
- Inconsistent with rest of page

**Include instead:**

- Intentional design that matches hero quality
- Maintained typography quality
- Consistent with page's design language
- Purposeful, not perfunctory

**Example instruction:**
"Footer should feel intentional, not like an afterthought. Maintain typography quality and design consistency. Should match the energy of the hero, not fade into generic link lists."

## Differentiation Requirements

Every design must include ONE unexpected element:

### Options for Unexpected Elements

Choose at least ONE unexpected element from the list below. You may combine multiple elements for greater impact:

1. **Oversized typography** - Display text that breaks the grid, creates impact
2. **Unusual grid structure** - Bento layout, diagonal sections, overlapping elements
3. **Distinctive hover states** - Unexpected interactions, animated transitions
4. **Section that breaks vertical rhythm** - Diagonal break, curved section, full-bleed image
5. **Bold use of whitespace** - Generous, asymmetric spacing that creates drama
6. **Unexpected color application** - Accent color used in surprising way
7. **Graphic element** - Custom shape, pattern, or illustration that's distinctive
8. **Typographic treatment** - Mixed weights, sizes, or orientations creatively

**In your design direction, specify which unexpected element(s) to include:**

"Include oversized typography in the hero section—display text that breaks the standard grid and creates immediate visual impact."

"Use an unusual grid structure with a bento-style layout where card sizes vary significantly, creating visual interest through asymmetry."

## Consistency Requirements

Design quality must not degrade as the page progresses:

### Common Quality Degradation Patterns

1. **Hero is bold, footer is generic** - Energy drops off
2. **Creative sections become safe** - Design gets more template-like
3. **Typography quality declines** - Headings get less attention
4. **Whitespace becomes uniform** - Loses purposeful spacing
5. **Color use becomes timid** - Accent colors fade away

### Consistency Instructions to Include

"CRITICAL: Footer and CTA sections should match the quality of the hero. Don't let the design get safer as the page progresses."

"Maintain design energy throughout—the last section should have the same intentionality as the first."

"Typography quality must remain consistent. Footer headings deserve the same attention as hero headings."

"Whitespace should remain purposeful throughout, not become uniform padding."

## Todo Item Structure

### 1. Design Direction Reference

First todo should capture the full design concept:

"Apply design direction: [aesthetic summary] with [layout approach] and [differentiation element]. Color direction: [emotional intent]. Typography: [mood]. Avoid [specific clichés]."

**Example:**
"Apply design direction: Clean, capable aesthetic for small team productivity software with staggered two-column layout and oversized typography in hero. Color direction: Light base with ONE vibrant accent (not blue) used sparingly. Typography: Friendly but professional. Avoid icon grids for features."

### 2. Image Search (if needed)

Be specific about what images are for, not just "hero background":

- ✅ "Search for product UI screenshots showing the tool in action"
- ✅ "Find portfolio project images with varied compositions"
- ✅ "Search for blog post cover images with editorial quality"
- ❌ "Search for hero background image"
- ❌ "Find generic images"

### 3. Build Homepage with Design Specifics

Include layout and style instructions:

"Build homepage (index.tsx) with [specific layout], [typography treatment], [section approach]. DO NOT use [specific cliché]. Include [differentiation element]."

**Example:**
"Build homepage (index.tsx) with asymmetric hero (text left, product shot right), features shown through inline examples (not icon grid), and integrated CTA section. Include oversized typography in hero. Maintain design energy through footer."

### 4. Add Images with Guidance

Specify how images should be used:

- ✅ "Add product screenshots to alternating feature sections with proper context"
- ✅ "Add portfolio images to bento grid with varied sizes"
- ❌ "Add images to homepage"

### 5. Header/Footer/Title with Brand Styling

Include design direction for navigation and page title:

"Update header, footer, and page title with [specific styling approach matching design direction]"

**Example:**
"Update header, footer, and page title with clean, minimal styling. Header should use friendly typography, footer should maintain design quality with purposeful layout. Page title should reflect the product name."

### 6. Choose Color Scheme

**CRITICAL: Always include color scheme selection as a separate step at the end.**

This allows the develop agent to build the structure first, then hand off to the color-scheme agent for palette selection.

"Choose color scheme that matches [emotional positioning] aesthetic"

**Example:**
"Choose color scheme that matches warm, inviting aesthetic for Italian restaurant"

### 7. Ask About Next Phase

Always end by listing deferred features:

"Ask user if they want to build: [specific list of deferred pages/features]"

## Template File Structure

The template has this structure:

```
src/
├── pages/
│   └── index.tsx          # Homepage (currently uses DemoContent)
├── routes.tsx             # Route definitions
├── App.tsx                # App setup with RootLayout config
├── layouts/
│   └── RootLayout.md      # Documentation for header/footer config
└── components/
    └── ui/                # Reusable UI components
```

## Single Page Preview Only

**CRITICAL: Only build index.tsx (homepage) in the initial preview.**

- Edit `index.tsx` to replace DemoContent with homepage content
- DO NOT create additional page files
- DO NOT add routes for other pages
- Defer all additional pages to future phases

## What to Defer

**ALWAYS defer to future phases:**

- **Multiple pages** - About, contact, services, blog posts, product details
- **API/Database features**:
  - Login/authentication forms
  - Contact forms or data submission
  - User accounts or profiles
  - Dynamic data from databases
  - Shopping carts or checkout
  - Real-time data or integrations
  - File uploads
  - Search functionality with backend

## Remember

Your goal is to create a **design concept** that results in a **distinctive, high-quality preview**:

1. Analyze product category, audience, and emotional positioning
2. Generate specific visual direction with emotional intent
3. Apply category-specific cliché avoidance
4. Include section-specific instructions
5. Specify differentiation requirements
6. Ensure consistency requirements
7. Create design-aware todo items
8. Provide complete design direction in handoff

The develop agent will follow your design direction to build a preview that stands out from generic templates.
