## App Template Directives

This template uses Vite + React 19 with the following specific tools:

- **Frontend**: Vite + React 19 with TypeScript
- **UI**: shadcn UI components (fully configured)
- **Styling**: Tailwind CSS with custom config
- **API**: vite-plugin-api for `/api/*` routes
- **Testing**: Vitest framework
- **Development**: Source-mapper + dev-tools integration
- **State**: React hooks, Context API, Zustand for complex state

## Template Structure

### Key Configuration Files

- **`vite.config.ts`**: Vite + source-mapper + dev-tools + vite-plugin-api
- **`components.json`**: shadcn UI aliases (`@/components`, `@/lib`, etc.)
- **`tailwind.config.js`**: Custom animations and theme extensions
- **Development tools**: `dev-tools/` and `source-mapper/` subdirectories
- **Scripts**: `dev-start.js` for development server management

### Source Directory (`src/`)

```
src/
├── components/
│   └── ui/                 # Complete shadcn UI library (40+ components)
├── layouts/                # Website.tsx & Dashboard.tsx with .md docs
│   └── parts/              # Header.tsx, Footer.tsx
├── lib/
│   ├── utils.ts            # shadcn utilities (cn, etc.)
│   └── api-client.ts       # Fetch helpers for /api routes
├── pages/
│   ├── index.tsx           # Default home page
│   └── _404.tsx            # Error page
├── api/                    # vite-plugin-api handlers → /api/*
├── styles/
│   └── globals.css         # Tailwind + CSS variables
├── App.tsx                 # Router setup
├── main.tsx                # React 19 root
└── routes.tsx              # Route definitions
```

## Layout System (MANDATORY USAGE)

### Available Layouts

- **`RootLayout`** (`src/layouts/RootLayout.tsx`): Centralized wrapper for multi-page websites
- **`Dashboard`** (`src/layouts/Dashboard.tsx`): Admin panels, SaaS apps, internal tools

### CRITICAL Layout Rules

1. **For multi-page websites**: Use RootLayout - configure header/footer once in `App.tsx`
2. **For dashboards/admin**: Use Dashboard layout directly in pages
3. **ALWAYS read layout documentation**: `src/layouts/RootLayout.md` or `Dashboard.md`
4. **NEVER** duplicate header/footer config across pages
5. **NEVER** create custom `min-h-screen` page containers

### Quick Start

**For public websites** - Read `src/layouts/RootLayout.md` for complete setup:

- Configure header/footer in `App.tsx` (once for entire site)
- Pages render content only, no layout concerns
- Follows React Router conventions

**For dashboards** - Read `src/layouts/Dashboard.md` for complete setup:

- Use Dashboard component directly in pages or as route wrapper
- Configure sidebar navigation and user info
- Includes sidebar, header, and content areas

### Component Architecture

- **RootLayout**: Wraps Website layout with centralized header/footer
- **Website**: Structural container (min-h-screen, flex-col, background)
- **Dashboard**: Complete admin layout (sidebar + header + content)
- **Header/Footer**: Navigation components in `src/layouts/parts/`
- **UI Components**: `src/components/ui/*` (40+ shadcn components)
- **Pages**: Content only (no layout when using RootLayout)

### Client Integration

- Use `src/lib/api-client.ts` for API helpers
- Standard fetch calls to `/api/*` endpoints
- TypeScript support for request/response types

### File Organization

- **Unified codebase**: Frontend + API in single `src/` directory
- **Component files**: Always separate `.tsx` files for components
- **Type safety**: Strict TypeScript configuration
- **Import aliases**: Use `@/` for `src/` paths (configured in `components.json`)

## Color System & CSS Variables

The template uses a comprehensive CSS variable system defined in `src/styles/globals.css`. All colors use HSL format (hue, saturation, lightness) without the `hsl()` wrapper for Tailwind compatibility.

**CRITICAL**: Always use CSS variables for colors. Never hard-code color values unless they are outside the template's color system scope (e.g., image overlays). This ensures colors adapt when users customize the theme.

### Core Color Variables

**Base Colors:**

- `--background`: Page background color
- `--foreground`: Primary text color
- `--card`: Card background
- `--card-foreground`: Card text color
- `--popover`: Popover background
- `--popover-foreground`: Popover text

**Brand Colors:**

- `--primary`: Primary brand color
- `--primary-foreground`: Text on primary
- `--secondary`: Secondary brand color
- `--secondary-foreground`: Text on secondary
- `--accent`: Accent color
- `--accent-foreground`: Text on accent

**UI Colors:**

- `--muted`: Muted background
- `--muted-foreground`: Muted text
- `--destructive`: Error/danger color
- `--destructive-foreground`: Text on destructive
- `--border`: Border color
- `--input`: Input border color
- `--ring`: Focus ring color (matches primary)

### Extended Colors

**Chart Colors:**

- `--chart-1` through `--chart-5`: Predefined chart color palette

### Sidebar Colors

**Dashboard Sidebar:**

- `--sidebar`: Sidebar background
- `--sidebar-foreground`: Sidebar text
- `--sidebar-primary`: Sidebar primary accent
- `--sidebar-primary-foreground`: Text on sidebar primary
- `--sidebar-accent`: Sidebar accent
- `--sidebar-accent-foreground`: Text on sidebar accent
- `--sidebar-border`: Sidebar border
- `--sidebar-ring`: Sidebar focus ring

### Typography Variables

- `--font-sans`: System sans-serif stack
- `--font-serif`: System serif stack
- `--font-mono`: System monospace stack

### Other Variables

- `--radius`: Border radius (0.5rem)
- `--shadow-2xs` through `--shadow-2xl`: Shadow definitions

### Usage in Tailwind

**Always prefer CSS variables over hard-coded colors.** All variables are available as Tailwind utilities:

```tsx
// Background colors - use CSS variables
<div className="bg-background">...</div>
<div className="bg-primary">...</div>
<div className="bg-muted">...</div>
<div className="bg-card">...</div>

// Text colors - use CSS variables
<p className="text-foreground">...</p>
<p className="text-primary">...</p>
<p className="text-muted-foreground">...</p>
<p className="text-card-foreground">...</p>

// Border colors - use CSS variables
<div className="border border-border">...</div>
<div className="border border-input">...</div>

// Using in inline styles (with hsl wrapper)
<div style={{ background: `hsl(var(--primary))` }}>...</div>
```

**Avoid hard-coding colors:**

```tsx
// ❌ Don't hard-code colors
<div className="bg-purple-500">...</div>
<div style={{ color: '#ff0000' }}>...</div>

// ✅ Use CSS variables instead
<div className="bg-primary">...</div>
<div className="text-destructive">...</div>
```

### Customizing Colors

To customize the color scheme, edit the CSS variables in `src/styles/globals.css`. Colors use HSL format (space-separated values) for Tailwind compatibility:

```css
:root {
  --primary: <hue> <saturation>% <lightness>%; /* HSL values without hsl() wrapper */
}
```

Tailwind will automatically wrap these with `hsl()` when used in classes like `bg-primary`. Users can customize these values to match their brand colors.

### Gradient Overlays on Images

**Exception**: Image overlays are outside the template's color system scope, so hard-coded gray gradients are acceptable here.

When adding overlays over images (for text readability, hero sections, etc.), **avoid using brand color overlays** as they can clash with image colors and look unprofessional. Instead, use **standard Tailwind gray gradient overlays** for a clean, neutral effect that works with any image.

**Recommended Pattern:**

```tsx
// Hero section with image and overlay
<div className="relative">
  <img src="/hero.jpg" alt="Hero" className="w-full h-full object-cover" />
  <div className="absolute inset-0 bg-gradient-to-b from-gray-900/60 to-gray-900/80" />
  <div className="relative z-10">
    {/* Content overlaid on image */}
    <h1 className="text-white">Hero Title</h1>
  </div>
</div>

// Card with image overlay
<div className="relative overflow-hidden rounded-lg">
  <img src="/card.jpg" alt="Card" className="w-full h-full object-cover" />
  <div className="absolute inset-0 bg-gradient-to-t from-gray-900/70 via-gray-900/40 to-transparent" />
  <div className="absolute bottom-0 left-0 right-0 p-6 text-white">
    {/* Content */}
  </div>
</div>
```

**Available Tailwind Gray Gradients:**

- `from-gray-900/60 to-gray-900/80` - Strong dark overlay (good for hero sections)
- `from-gray-900/70 via-gray-900/40 to-transparent` - Gradient fade (good for cards)
- `from-gray-800/50 to-gray-900/70` - Medium-dark overlay
- `from-black/60 to-black/80` - Pure black overlay (alternative to gray-900)

**Opacity Levels:**

Use Tailwind's opacity modifiers (`/60`, `/70`, `/80`, etc.) to control overlay intensity:

- `/40` - Light overlay (subtle)
- `/50` - Medium overlay
- `/60` - Medium-dark overlay
- `/70` - Dark overlay
- `/80` - Very dark overlay

**Why Gray Instead of Color:**

- **Neutral**: Gray overlays work with any image color palette
- **Professional**: Avoids color clashes that can occur with brand color overlays
- **Readable**: Provides consistent contrast for text readability
- **Versatile**: Works across different image styles and themes
