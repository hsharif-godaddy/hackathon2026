# v8 Template - Simplified Full-Stack React

## Overview

v8 is a simplified full-stack React template that combines the proven dev tools from v3 with a streamlined single-codebase architecture. It eliminates the complexity of frontend/backend separation while maintaining powerful development tools and modern API functionality.

## Key Features

- ✅ **Working Dev Tools**: Fully functional source-mapper and development tools from v3
- ✅ **Hot Module Replacement**: Fast development with React Fast Refresh
- ✅ **Single Codebase**: No frontend/backend directory split
- ✅ **Modern API**: Built-in API routes with vite-plugin-api (when compatible)
- ✅ **Full Type Safety**: TypeScript throughout
- ✅ **Component Library**: Complete shadcn/ui setup

## Config Files

- **`vite.config.ts`**: Vite configuration with source-mapper and dev-tools integration
- **`components.json`**: shadcn UI configuration with aliases and styling
- **`package.json`**: Simplified scripts and dependencies (no backend complexity)
- **`tsconfig.json`**: TypeScript configuration for the unified codebase
- **`tailwind.config.js`**: Tailwind CSS configuration with animations and plugins
- **`postcss.config.js`**: PostCSS configuration for Tailwind CSS processing

## Directory Structure

```
src/
├── components/             # Reusable React components
│   └── shadcn/             # shadcn UI components (button, card, etc.)
├── layouts/                # Layouts for the main app structure
│   └── parts/              # Reusable parts consumed by layouts
├── lib/                    # Utility functions and helpers
├── pages/                  # Initial page components for routing
├── styles/                 # Global styles and CSS
├── api/                    # API endpoint handlers (vite-plugin-api)
├── App.tsx                 # Root application component
└── main.tsx                # Application entry point
```

## UI Building Patterns

A set of components, libraries and patterns are available for you to create a professional and compeling Website or application. Components structure is defined as following :
- **Layouts** Highest structure in your app, defining the global visual template
- **Components** Lowest, smallest, atomic-like parts used to build most UI elements.
  - /shadcn : Shadcn UI components library that can be reused when building components and layouts

### Layouts

You are to pick one, and only one, layout as the main template for your application, based on user's needs. Layouts are located at (`src/layouts/`)

- **`Website`**: A complete website layout with configurable header and footer (for landing pages, marketing sites, and web applications). Default layout for most usages.
- **`Dashboard`**: A complete dashboard layout with sidebar navigation, header with search/user menu, and main content area (for admin panels, SaaS applications, and internal tools).

#### Layouts Usage Guidelines

**MANDATORY READING BEFORE IMPLEMENTATION**:

When you select a layout for the application, you MUST follow this exact process:

1. **SELECT** the appropriate layout based on user requirements:
   - Use **`Website`** for: landing pages, marketing sites, public-facing websites, portfolios
   - Use **`Dashboard`** for: admin panels, SaaS applications, internal tools, analytics dashboards
2. **READ** the layout's documentation file COMPLETELY:
   - **`Website`** → Read `src/layouts/Website.md` (comprehensive usage guide)
   - **`Dashboard`** → Read `src/layouts/Dashboard.md` (comprehensive usage guide)
3. **READ** the layout's implementation file:
   - **`Website`** → Read `src/layouts/Website.tsx` (actual component code)
   - **`Dashboard`** → Read `src/layouts/Dashboard.tsx` (actual component code)
4. **IMPLEMENT** pages using the layout as shown in the documentation

**CRITICAL REQUIREMENTS**:
- ✅ **ALL PAGES** must be wrapped in your chosen layout component
- ✅ **NEVER CREATE** standalone pages with `min-h-screen` or custom layouts
- ✅ **ALWAYS FOLLOW** the patterns shown in the layout's .md documentation
- ❌ **NEVER GUESS** at configuration - the .md file has complete examples

**Example Process**:

For a landing page:
```
1. User wants a landing page → Choose Website layout
2. Read src/layouts/Website.md completely
3. Read src/layouts/Website.tsx to understand props
4. Implement ALL pages wrapped in <Website config={{...}}>
```

**Never skip reading the layout documentation** - it contains critical usage patterns, configuration examples, and anti-patterns to avoid.

## Technology Stack (MANDATORY)

You must ONLY work with this specific technology stack:

- **Frontend Framework**: Vite + React 19
- **UI Library**: React with TypeScript
- **Component Library**: shadcn UI (complete setup included)
- **Styling**: Tailwind CSS exclusively
- **State Management**: React hooks, Context API, or Zustand for complex state
- **API Layer**: vite-plugin-api for serverless-style API routes
- **Build Tool**: Vite for fast development and building
- **Testing**: Vitest for unit and integration tests
- **Development Tools**: Source-mapper + dev-tools for enhanced debugging

## API Development

### API Route Structure
API routes are defined in `src/api/` and automatically served at `/api/*`:

```typescript
// src/api/users.ts → serves /api/users
export default function handler(req: Request) {
  if (req.method === 'GET') {
    return new Response(JSON.stringify([
      { id: 1, name: 'John', email: 'john@example.com' }
    ]), {
      headers: { 'Content-Type': 'application/json' }
    });
  }
  
  return new Response('Method not allowed', { status: 405 });
}
```

### API Client Pattern
Frontend communicates with API through fetch calls:

```typescript
// src/lib/api-client.ts
export async function fetchUsers() {
  const response = await fetch('/api/users');
  return response.json();
}
```

## Architecture Principles

- **Unified Codebase**: Single repository with both frontend and API code
- **Component Separation**: Always create separate files for React components  
- **Type Safety**: Use TypeScript throughout
- **Responsive Design**: Use Tailwind CSS with shadcn UI for all styling
- **Web Standards**: API routes use standard Request/Response objects
- **Development Experience**: Source-mapper provides file/line debugging in browser

## Development Tools

### Source Mapper
- **File Attribution**: Adds `data-dev-file` attributes to JSX elements
- **Component Tracking**: Includes `data-dev-component` for component identification
- **Line Numbers**: Provides `data-dev-line` for precise code location
- **Browser Integration**: Click elements in dev tools to jump to source code

### Dev Tools Provider
- **Development Mode Detection**: Automatically enables in development
- **Hot Reload Compatible**: Works seamlessly with Vite HMR
- **Visual Debugging**: Overlays and component inspection in browser

## Style Guide

Follow the same shadcn/ui patterns as v3:

### Button Components
- **`variant="default"`**: Primary actions with brand colors
- **`variant="outline"`**: Secondary actions (works on all backgrounds)
- **`variant="ghost"`**: Subtle actions with transparent background
- **`variant="secondary"`**: Light gray background (white backgrounds only)
- **`variant="destructive"`**: For delete/remove actions
- **`variant="link"`**: Text-style buttons for navigation

### Recommended Patterns
```tsx
// Primary + Secondary combination
<Button variant="default">Get Started</Button>
<Button variant="outline">Learn More</Button>

// Form actions
<Button variant="default">Save</Button>
<Button variant="ghost">Cancel</Button>
```

The `outline` variant is specifically designed to work on any background by inheriting proper theme colors.
