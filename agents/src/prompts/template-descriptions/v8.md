## App Template Directives

This template uses Vite + React 19 with the following specific tools:

- **Frontend**: Vite + React 19 with TypeScript
- **UI**: shadcn UI components (fully configured)
- **Styling**: Tailwind CSS with custom config
- **API**: vite-plugin-api for `/api/*` routes
- **Testing**: Vitest framework
- **Development**: Source-mapper + dev-tools integration
- **State**: React hooks, Context API, Zustand for complex state

## Template Structure

### Key Configuration Files

- **`vite.config.ts`**: Vite + source-mapper + dev-tools + vite-plugin-api
- **`components.json`**: shadcn UI aliases (`@/components`, `@/lib`, etc.)
- **`tailwind.config.js`**: Custom animations and theme extensions
- **Development tools**: `dev-tools/` and `source-mapper/` subdirectories
- **Scripts**: `dev-start.js` for development server management

### Source Directory (`src/`)

```
src/
├── components/
│   └── ui/                 # Complete shadcn UI library (40+ components)
├── layouts/                # Website.tsx & Dashboard.tsx with .md docs
│   └── parts/              # Header.tsx, Footer.tsx
├── lib/
│   ├── utils.ts            # shadcn utilities (cn, etc.)
│   └── api-client.ts       # Fetch helpers for /api routes
├── pages/
│   ├── index.tsx           # Default home page
│   └── _404.tsx            # Error page
├── api/                    # vite-plugin-api handlers → /api/*
├── styles/
│   └── globals.css         # Tailwind + CSS variables
├── App.tsx                 # Router setup
├── main.tsx                # React 19 root
└── routes.tsx              # Route definitions
```

## Layout System (MANDATORY USAGE)

### Available Layouts

- **`RootLayout`** (`src/layouts/RootLayout.tsx`): Centralized wrapper for multi-page websites
- **`Dashboard`** (`src/layouts/Dashboard.tsx`): Admin panels, SaaS apps, internal tools

### CRITICAL Layout Rules

1. **For multi-page websites**: Use RootLayout - configure header/footer once in `App.tsx`
2. **For dashboards/admin**: Use Dashboard layout directly in pages
3. **ALWAYS read layout documentation**: `src/layouts/RootLayout.md` or `Dashboard.md`
4. **NEVER** duplicate header/footer config across pages
5. **NEVER** create custom `min-h-screen` page containers

### Quick Start

**For public websites** - Read `src/layouts/RootLayout.md` for complete setup:

- Configure header/footer in `App.tsx` (once for entire site)
- Pages render content only, no layout concerns
- Follows React Router conventions

**For dashboards** - Read `src/layouts/Dashboard.md` for complete setup:

- Use Dashboard component directly in pages or as route wrapper
- Configure sidebar navigation and user info
- Includes sidebar, header, and content areas

### Component Architecture

- **RootLayout**: Wraps Website layout with centralized header/footer
- **Website**: Structural container (min-h-screen, flex-col, background)
- **Dashboard**: Complete admin layout (sidebar + header + content)
- **Header/Footer**: Navigation components in `src/layouts/parts/`
- **UI Components**: `src/components/ui/*` (40+ shadcn components)
- **Pages**: Content only (no layout when using RootLayout)

### Client Integration

- Use `src/lib/api-client.ts` for API helpers
- Standard fetch calls to `/api/*` endpoints
- TypeScript support for request/response types

### File Organization

- **Unified codebase**: Frontend + API in single `src/` directory
- **Component files**: Always separate `.tsx` files for components
- **Type safety**: Strict TypeScript configuration
- **Import aliases**: Use `@/` for `src/` paths (configured in `components.json`)

## Available UI Components (shadcn)

### Complete Component Library

All shadcn UI components are pre-installed in `src/components/ui/`:

- **Forms**: button, input, textarea, select, checkbox, switch, etc.
- **Layout**: card, separator, tabs, accordion, sheet, dialog, etc.
- **Navigation**: navigation-menu, breadcrumb, pagination, command, etc.
- **Feedback**: alert, toast (sonner), progress, skeleton, etc.
- **Data**: table, calendar, form, hover-card, popover, etc.

### Import Pattern

```tsx
import { Button } from '@/components/ui/button';
import { Card, CardContent, CardHeader } from '@/components/ui/card';
```

### Anchor Link Pattern

For navigation with hash links (#section), ensure corresponding IDs exist:

```tsx
// Navigation
{ href: '#features', label: 'Features' }
// Content
<section id="features">...</section>
```

## Template-Specific Constraints

### Required Tools Usage

- **MUST** use RootLayout pattern for multi-page sites (configure in `App.tsx`)
- **MUST** read layout `.md` documentation before implementation
- **MUST** use shadcn UI components from `@/components/ui/`
- **MUST** follow vite-plugin-api patterns for backend functionality
- **MUST** use TypeScript with strict configuration
- **MUST NOT** duplicate header/footer config across pages
