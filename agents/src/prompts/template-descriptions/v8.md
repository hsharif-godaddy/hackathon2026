# App Template (v8)

Vite + React 19 with TypeScript, shadcn UI, Tailwind CSS, and an explicit Express server in `src/server/entry.ts`.

## Tech Stack

- **Frontend**: Vite + React 19 + TypeScript
- **UI**: shadcn UI components (40+ pre-installed)
- **Styling**: Tailwind CSS with CSS variables
- **Animation**: Motion for animations and transitions
- **API**: Explicit Express handlers registered in `src/server/entry.ts` for `/api/*` routes
- **SSR**: `renderToString` in `src/entry-server.tsx` with `HelmetProvider`. Routing uses React Router v7 data routers: `createStaticHandler` + `StaticRouterProvider` on the server, `createBrowserRouter` + `RouterProvider` on the client. `src/App.tsx` is client-only; the server imports `routes` + `RootLayout` directly.
- **Testing**: Vitest
- **State**: React hooks, Context API, Zustand
- **SEO**: `@dr.pogodin/react-helmet` (required for SSR head collection - see `develop/seo.md`)

## Layout System

- **RootLayout** (`src/layouts/RootLayout.tsx`): Multi-page websites with shared header/footer

### Critical Rules

1. **ALWAYS read `App.tsx` first** before modifying routes or layouts
2. **Read layout `.md` documentation** before implementation

## Animation (Motion)

Import: `import { motion } from "motion/react"`

**Props**: `initial`, `animate`, `whileInView` (with `viewport={{ once: true }}`), `whileHover`, `whileTap`, `exit`

**Variants**: Use `staggerChildren` in parent, named states in children. Add `as const` to variant objects to preserve ease literal types.

**Transition**: `{ duration, delay, ease, repeat, repeatType }`. Ease values: `"linear"` | `"easeIn"` | `"easeOut"` | `"easeInOut"` | `"circIn"` | `"circOut"` | `"circInOut"` | `"backIn"` | `"backOut"` | `"backInOut"` | `"anticipate"` | `[n,n,n,n]`

⚠️ **Use `as const` on variant/transition objects** — TypeScript widens ease strings to `string` which doesn't match the `Easing` type:

```tsx
const variants = {
  hidden: { opacity: 0, y: 20 },
  visible: { opacity: 1, y: 0, transition: { duration: 0.5, ease: 'easeOut' as const } },
} as const;
```

**Timing**: Hover 150-200ms, entrance 300-500ms, ambient 3-8s with `repeat: Infinity`

## SEO and Document Head

Every page is server-side rendered. Use `@dr.pogodin/react-helmet` for all head management - it collects head state on the server and serializes it into the HTML response. React 19 native metadata tags do not work under this SSR setup because they do not provide a server state collector.

**Site-wide defaults** (the `<title>` and `<meta name="description">` that should apply to every page) live in a `<Helmet>` inside `src/layouts/RootLayout.tsx`. To change the site title or default description, edit that `<Helmet>` — do **not** edit `index.html`. Per-page `<Helmet>` blocks in route components override the RootLayout defaults (last-mounted wins).

```tsx
import { Helmet } from '@dr.pogodin/react-helmet';

export default function AboutPage() {
  const title = 'About - Acme';
  const description = 'Learn about our 20 year track record.';
  const canonicalUrl = 'https://acme.example/about';
  const ogImage = new URL('/api/og', canonicalUrl);
  ogImage.searchParams.set('title', title);
  ogImage.searchParams.set('description', description);
  const jsonLd = {
    '@context': 'https://schema.org',
    '@type': 'AboutPage',
    name: title,
    url: canonicalUrl,
  };

  return (
    <>
      <Helmet>
        <title>{title}</title>
        <meta name="description" content={description} />
        <link rel="canonical" href={canonicalUrl} />
        <meta property="og:title" content={title} />
        <meta property="og:description" content={description} />
        <meta property="og:image" content={ogImage.href} />
        <meta property="og:url" content={canonicalUrl} />
        <meta property="og:type" content="website" />
        <meta name="twitter:card" content="summary_large_image" />
        <meta name="twitter:image" content={ogImage.href} />
        <script type="application/ld+json">{JSON.stringify(jsonLd)}</script>
      </Helmet>
      <section>{/* page content */}</section>
    </>
  );
}
```

See `develop/seo.md` for the full reference: Open Graph, Twitter, JSON-LD structured data, image hygiene, semantic HTML, and the pre-completion checklist.

## Data Fetching

For data that **must appear in the server-rendered HTML** (anything a search crawler or social preview should see — product details, blog content, listing pages), use a route `loader` in `src/routes.tsx`. The data router runs loaders on the server before render, so the HTML ships with data instead of a loading state that crawlers miss and users wait on.

```tsx
// routes.tsx
import type { RouteObject } from 'react-router-dom';
import ProductPage from './pages/products/[id]';

export const routes: RouteObject[] = [
  {
    path: '/products/:id',
    element: <ProductPage />,
    loader: async ({ params }) => {
      const res = await fetch(`https://api.example.com/products/${params.id}`);
      if (!res.ok) throw new Response(null, { status: res.status });
      return { product: await res.json() };
    },
  },
];

// pages/products/[id].tsx
import { useLoaderData } from 'react-router-dom';

export default function ProductPage() {
  const { product } = useLoaderData() as { product: { name: string } };
  return <h1>{product.name}</h1>;
}
```

Loaders are plain async functions — no React hooks, no `window`/`document` access. A thrown `Response` sets the HTTP status of the SSR response (so `throw new Response(null, { status: 404 })` returns a real 404 code). The crawler gets the correct status, but the body is a blank fallback shell — **pair the thrown `Response` with a route `errorElement`** (below) if you want the user to see a not-found or error page instead of an empty page.

Use `useEffect(() => fetch(...))` **only** for data that is client-only (post-hydration interactions, user-triggered refetches, data that doesn't need to be indexed).

## Per-Route Error Boundaries

Each route can declare an `errorElement`. When its loader throws or its component errors during render, only that route's subtree swaps to the error UI — the layout (header, footer, navigation) stays mounted and interactive. Use it for any page where "whole site crashes" is a worse UX than "this section failed".

```tsx
{
  path: '/products/:id',
  element: <ProductPage />,
  errorElement: <ProductError />,
  loader: productLoader,
}

// ProductError.tsx
import { useRouteError, isRouteErrorResponse } from 'react-router-dom';
export default function ProductError() {
  const error = useRouteError();
  if (isRouteErrorResponse(error) && error.status === 404) return <p>Product not found.</p>;
  return <p>Something went wrong.</p>;
}
```

## SSR Markers in index.html

`index.html` contains two reserved placeholder markers used by the SSR path:

- `<!--app-head-->` - replaced at request time with head output collected by react-helmet
- `<!--app-html-->` - replaced at request time with the rendered page markup

Never remove or rename these markers - the server render will fail without them.

## Required Practices

- **MUST** read `App.tsx` before modifying routes/layouts
- **MUST** use RootLayout for multi-page sites
- **MUST** read layout `.md` docs before implementation
- **MUST** use shadcn components from `@/components/ui/`
- **MUST** use `@/` import aliases
- **MUST** use `@dr.pogodin/react-helmet` (`<Helmet>`) for page-specific titles, meta, canonical, Open Graph, noindex, and JSON-LD
- **MUST** edit the `<Helmet>` in `src/layouts/RootLayout.tsx` to change the site-wide default `<title>` / `<meta name="description">`
- **MUST NOT** add or edit `<title>`, `<meta>`, or `<link>` tags in `index.html`. Head management is owned by `<Helmet>` at render time; duplicating head tags in the static shell produces duplicate `<title>` tags in the served HTML, which violates the HTML spec and confuses crawlers.
- **MUST NOT** hard-code color values
- **MUST NOT** duplicate header/footer config
- **MUST NOT** modify `index.html` entry point imports. The `import('/src/main.tsx')` pattern is intentional — Vite rewrites it during build to point at bundled output (e.g., `import('/assets/main-abc123.js')`). Adding `/* @vite-ignore */`, cache-busting query params, or rewriting the import logic disables this transform, causing 404 errors in the published app.
- The build produces `dist/client/` (SPA assets and the SSR'd `index.html` template) and `dist/server.bundle.mjs` (Express server with API handlers and the SSR render path). Publishing serves `dist/server.bundle.mjs`. Do not remove or alter the `vite build && vite build --ssr src/server/entry.ts` pair in the build script.
- Production runs Alpine (musl), which cannot load glibc-compiled native addons (bcrypt, sharp, canvas crash). Use pure-JS alternatives: bcryptjs, jimp.
