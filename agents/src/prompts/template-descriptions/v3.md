# Vite + React + shadcn/ui Template

## Config files

- **`vite.config.ts`**: Vite configuration for build and development settings
- **`components.json`**: shadcn UI configuration with aliases and styling
- **`package.json`**: Contains scripts (`build`, `lint`) and dependencies
- **`tsconfig.json`**: TypeScript compiler configuration for the project
- **`tailwind.config.js`**: Tailwind CSS configuration with animations and plugins
- **`postcss.config.js`**: PostCSS configuration for Tailwind CSS processing

## Component Organization Strategy

As you develop the application, follow this Vite + React organization:

```
src/
├── frontend/                 # Frontend application code
│   ├── components/          # Reusable React components
│   │   ├── ui/              # shadcn UI components (button, card, etc.)
│   │   └── layout/          # Layout components (Header, Footer, etc.)
│   ├── pages/               # Page components for routing
│   ├── lib/                 # Utility functions and helpers
│   ├── styles/              # Global styles and CSS
│   ├── api/                 # API client code
│   ├── hooks/               # Custom React hooks
│   └── App.tsx              # Root application component
├── backend/                  # Backend API code
│   ├── api/                 # API routes and handlers
│   ├── utils/               # Backend utilities
│   └── index.ts             # Server entry point
├── shared/                   # Shared code between frontend/backend
│   ├── constants/           # Application constants
│   ├── utils/               # Shared utility functions
│   └── types/               # Shared TypeScript types
└── test/                     # Test configuration and utilities
```

## Technology Stack (MANDATORY)

You must ONLY work with this specific technology stack:

- **Frontend Framework**: Vite + React
- **UI Library**: React with TypeScript
- **Component Library**: shadcn UI
- **Styling**: Tailwind CSS exclusively
- **State Management**: React hooks, Context API, or Zustand for complex state
- **Backend**: Node.js/Express (separate from frontend)
- **Build Tool**: Vite for fast development and building
- **Testing**: Vitest for unit and integration tests
- **Development**: Concurrent frontend and backend development

## Architecture Principles

- **Full-Stack Separation**: Frontend (Vite/React) and backend (Node/Express) as separate but coordinated applications
- **Component Separation**: Always create separate files for React components
- **File Organization**: Follow the established src/ directory structure
- **Type Safety**: Use TypeScript throughout both frontend and backend
- **Responsive Design**: Use Tailwind CSS with shadcn UI for all styling and responsive behavior
- **UI Components**: Leverage shadcn UI components for consistent, accessible interfaces

- **API Communication**: Frontend communicates with backend through well-defined API endpoints

## Database Integration

### Database Service Architecture
- **Use existing `src/backend/services/database.ts`** - Don't create new connection files
- **Pre-configured service**: Database connection handling is already implemented
- **Environment-based configuration**: Reads from `.env` file automatically
- **Docker compatibility**: Supports `host.docker.internal` for containerized development

### API Communication Pattern  
- **All API access via Vite proxy** (`/api/*` routes only)
- **Backend runs on port 3000** internally (not exposed externally)
- **Frontend uses dynamic ports** with Vite dev server
- **Proxy configuration**: Vite automatically proxies `/api/*` to backend

### Database Integration Workflow
- Database credentials are automatically written to `.env` file
- Backend service reads configuration from environment variables
- Server restart is automatic after database setup
- Frontend accesses database through API endpoints (via proxy)

### File Structure for Database
```
src/backend/
├── services/database.ts     # ✅ Use existing (pre-configured)
├── api/routes.ts           # Add database API endpoints here
└── migrations/             # Optional: database schema files
```

## Style Guide

### Button Components

The shadcn/ui Button component provides several variants optimized for different use cases:

- **`variant="default"`**: Primary actions with brand colors (purple/blue gradient)
- **`variant="outline"`**: Secondary actions with transparent background and border - works on all backgrounds
- **`variant="ghost"`**: Subtle actions with transparent background, no border
- **`variant="secondary"`**: Light gray background, use only on white backgrounds
- **`variant="destructive"`**: For delete/remove actions
- **`variant="link"`**: Text-style buttons for navigation

**Recommended patterns:**

```tsx
// Primary + Secondary
<Button variant="default">Get Started</Button>
<Button variant="outline">Learn More</Button>

// Form actions
<Button variant="default">Save</Button>
<Button variant="ghost">Cancel</Button>
```

The `outline` variant is specifically designed to work on any background color or image by inheriting the proper text color from the theme.
