# UXCore Usage

`@airo-ux/pattern-library` is built on GoDaddy UXCore2 (Antares). Every component
must compose `@ux/*` primitives and theme via intents. Never reimplement
primitives, never hardcode tokens, never restyle UXCore2 internals.

## Compose, don't reimplement

Prefer UXCore2 primitives over raw HTML + inline styles.

| Use for | Primitive |
|---------|-----------|
| Layout, spacing, stacking, padding | `@ux/box` — `<Box>` default `<div>`; `<box.section>`, `<box.article>`, etc. for semantic HTML |
| Heading + body combinations | `@ux/text-lockup` |
| Running text, headings | `@ux/text` (`text.h1`, `text.p`, `text.span`, …) |
| Buttons | `@ux/button` |
| Icons | `@ux/icon` |
| Status / category labels | `@ux/tag` (not `@ux/chip`, which is interactive) |

**Hand-rolling a primitive is a block.** A new component that uses `<div
className="flex flex-col gap-2">` instead of `<Box orientation="vertical"
gap="md">` is an Important finding. A new component that reimplements a
button with `<div onClick>` + role is Critical.

## Intent tokens only

No raw colour, spacing, font, or shadow values. All styling flows through one
of:

1. `@ux/tailwind-intents` utility classes (preferred for component-level
   styling in TSX and `styles.css`).
2. Bound intent variables in CSS (e.g. `intent('ux.box.foregroundColor')`).
3. `defaultTheme.spacing` / `borderRadius` from `@ux/intents` for any values
   that need to stay in sync with the UXCore theme scale.

**Blocks:**

- Raw hex / rgb / hsl / hsla anywhere in source (`#111`, `rgb(…)`,
  `hsla(…)`).
- Hardcoded font families (`font-family: 'Helvetica', …`).
- Arbitrary `px` / `rem` / `em` values outside the Tailwind config.
- `z-index: 9999` and similar magic numbers. Use DOM order or CSS Grid
  overlap.
- Opaque `--ux-<hash>` CSS custom properties (`var(--ux-1xkykcn, …)`,
  `var(--ux-97h3vl, lightgray)`, etc.). These are compiler-generated
  internals that rename on every UXCore release, and the fallback
  value is always the raw literal we're trying to avoid. See
  [Never consume opaque `@ux/*` CSS variables](#never-consume-opaque-ux-css-variables).

**Exception — shadows:** Literal `px` values for `box-shadow` or
`filter: drop-shadow` geometry (offset-x, offset-y, blur-radius, spread-radius)
are **permitted**. UXCore2/Antares does not expose tokens for shadow geometry.
Shadow **color** must be black with alpha only (e.g. `rgba(0, 0, 0, 0.08)`);
do not use `intent('ux.box.foregroundColor')` or other intents for shadows.
(Black-only `rgba` for shadow color is the one allowed raw RGB form — not for
fills, borders, or text.)

The rule covers inline styles, CSS, and Tailwind `className` attributes.
`className="mt-3 p-2"` is an Important finding — swap to
`<Box blockPadding="md" inlinePadding="sm">` or to an intent-aware Tailwind
class.

## Intent pairing

When using intent token pairs, foreground and background must come from the
same contrast level. Never mix levels.

| Background | Foreground |
|------------|-----------|
| `box.backgroundColor` | `box.foregroundColor` |
| `boxLowContrast.backgroundColor` | `boxLowContrast.foregroundColor` |
| `boxHighContrast.backgroundColor` | `boxHighContrast.foregroundColor` |

Mixing `boxLowContrast.backgroundColor` with `box.foregroundColor` is a
Critical finding — it produces unreadable content in the wrong theme.

## Never restyle `@ux/*` internals

UXCore2 controls its own internal DOM. Our components must compose or pass
variants/props. Never reach in with descendant selectors.

Blocks:

```css
/* BAD — hard block */
.airo-<area>-<name> .ux-button__label { … }
.ux-button--primary .icon { … }
```

Acceptable:

```css
/* GOOD — scope to your own BEM node */
.airo-<area>-<name>__trigger { … }
```

Pass the Airo component its own `className` and target **that**. If
you need behaviour that UXCore2 doesn't expose as a prop, raise it in
the UXCore repo or follow the Escalation path in
[`SKILL.md`](../SKILL.md) — don't patch around it with CSS.

## Never consume opaque `@ux/*` CSS variables

UXCore2 ships two kinds of CSS custom properties:

- **Named, semantic vars** — documented, consumer-facing, stable across
  majors. Names are kebab-case English (e.g. `--ux-intent-primary-color`,
  `--ux-box-inline-padding`). Safe to consume from component CSS.
- **Opaque, hash-suffixed vars** — auto-generated by the UXCore
  compile pipeline (Vanilla Extract / Linaria / scoped-CSS). The name
  after `--ux-` is a short alphanumeric hash such as `--ux-1xkykcn`,
  `--ux-97h3vl`, `--ux-1sbfig8`, `--ux-1n2ego0`. These are **internal
  implementation detail** — never safe to consume.

Using a hash-named variable is a **Critical** finding (rule
`uxcore-opaque-internal-var`) for three compounding reasons:

1. **The hash is regenerated on every UXCore release.** A silent
   rename means every consumer who imports our stylesheet suddenly
   renders the CSS-var *fallback* — bypassing the theme entirely.
2. **The fallback is usually a raw literal.** Authors who reach for a
   hash var typically write `var(--ux-97h3vl, lightgray)` or
   `var(--ux-1n2ego0, 0.875rem)`. That fallback triggers
   `uxcore-hardcoded-colour` / the "no raw `px`/`rem` outside the
   Tailwind config" rule the moment the hash changes. One finding, two
   ways to ship a broken theme.
3. **It signals the author peeked at the compiled UXCore stylesheet**
   instead of using the documented intent API. This is how internal
   coupling creeps into a supposedly composed component.

### How to tell them apart

| Variable name pattern | Classification | Action |
|-----------------------|----------------|--------|
| `--ux-<english-kebab-case>` (e.g. `--ux-intent-primary-color`) | Semantic / public | Safe — consume as-is. |
| `--ux-<hash>` where `<hash>` starts with a digit or is a terse alphanumeric blob with no internal hyphen (e.g. `--ux-97h3vl`, `--ux-1xkykcn`) | Opaque / internal | Critical — remove. |

### Grep pattern

```text
var\(--ux-[0-9]
var\(--ux-[a-z0-9]{5,}[,)]
```

The first catches any `--ux-*` whose name starts with a digit (semantic
UXCore tokens are always English words — none start with a digit). The
second catches short, hyphen-free alphanumeric blobs. Either pattern
matching is a Critical finding unless the reviewer can point at a
documented UXCore token with that exact name.

### What to do instead

Replace the hash reference with the semantic alternative from the
corresponding `@ux/*` primitive. If UXCore doesn't expose the value
you need as a documented token, take the **Escalation path**
(`SKILL.md` → Escalation path) and add the affordance to UXCore
itself. The rule is categorical: a hash var in our CSS is always a
bug, never a shortcut.

## Logical properties + container queries

Airo components are shipped globally. Use logical CSS properties and
container queries instead of physical and media queries:

- `padding-inline-start` over `padding-left`.
- `margin-block-end` over `margin-bottom`.
- `@container (min-width: 24rem)` over `@media (min-width: 24rem)` when the
  responsive behaviour is about the component's own size, not the viewport.

## Peer-dep boundary

All `@ux/*` packages are **peer dependencies**. They must never be moved to
`dependencies` and never be bundled into `dist`. Every `@ux/*` peer must stay
in the `^2400.0.0 || ^2500.0.0` range to support the two active UXCore2
majors (UXCore2 → Antares transition). A range change is a risk-surface
escalation (see [`SKILL.md`](../SKILL.md) → Escalation path), not a
drive-by bump.

See [`ALLOWED-LIBRARIES.md`](./ALLOWED-LIBRARIES.md) for the rules on
`react-aria`,
`react-stately`, `@godaddy/antares*`, and blocked third-party component
libraries.

## Review red flags

- `#000`, `#fff`, any hex — Important.
- `style={{ padding: '8px' }}` — Important (use `<Box>`).
- `className="bg-blue-500 text-white"` — Important if the underlying colour
  isn't an intent token. Use `@ux/tailwind-intents` utilities, not raw
  Tailwind colour utilities.
- `font-family: …` in source — Important.
- `.ux-*` descendant selectors — Critical.
- `var(--ux-<hash>)` — any `--ux-*` whose name isn't a kebab-case
  English phrase (starts with a digit, or is a terse alphanumeric blob
  like `--ux-1xkykcn`). Critical, rule `uxcore-opaque-internal-var`.
  Nearly always paired with a raw-literal fallback (`lightgray`,
  `0.875rem`, `1.5`) that's a second, independent Critical.
- `z-index: 9999` — Important.
- UXCore2 primitive moved from `peerDependencies` to `dependencies` —
  Critical.
- Import of `@ux/*` CSS from inside component code (e.g. via
  `import '@ux/box/styles'` in a `.tsx` file) — Important. Consumers opt in
  to styles via the component's `/styles` subpath; we don't auto-inject
  UXCore CSS.
